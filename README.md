# Capibara — аналитическая модель маркетплейса

Проект разработан в рамках хакатона Capibara. Его цель — построение аналитической модели данных маркетплейса, проверка корректности данных и выполнение SQL-запросов для анализа продаж.

Репозиторий содержит SQL-скрипты, сценарии запуска и проверки, инструменты демонстрации аналитической модели и документацию по архитектурным решениям.

## Цели проекта

Основные задачи проекта:

- Построить аналитическую модель данных маркетплейса.
- Организовать обработку исходных данных и подготовку аналитических сущностей.

## Архитектура данных

Модель предназначена для подготовки данных маркетплейса к аналитическому использованию.

В архитектуре рассматриваются следующие уровни:

| Слой | Назначение |
|---|---|
| `raw` | Исходные данные |
| `core` | Очищенные, типизированные и связанные аналитические сущности |
| `mart` | Возможный дополнительный слой подготовленных витрин и агрегатов |

Основной аналитический слой — `core`. Необходимость дополнительного слоя `mart` определяется требованиями к отчётности и производительности.

При построении модели важно учитывать зерно каждой таблицы и кардинальность связей. Например, позиции заказа и платежи следует агрегировать отдельно перед соединением на уровне заказа, чтобы избежать размножения строк и искажения сумм.

## Требования

Для работы с проектом необходимы:

- Git;
- Docker и Docker Compose;
- Bash-совместимая оболочка — например, Git Bash или WSL в Windows;
- доступ к базе данных и исходным данным, предусмотренным конфигурацией проекта.

## Запуск проекта

Клонируйте репозиторий:

```bash
git clone https://github.com/ILYA88G/rwb_hac.git
cd rwb_hac
```

Проверьте состояние контейнеров:

```bash
docker compose ps
```

Перед запуском сценариев убедитесь, что необходимые сервисы запущены, а исходные данные доступны. Порядок первоначальной настройки зависит от конфигурации окружения и инструкций в скриптах проекта.

## Команды для работы с аналитической моделью

Все команды выполняются из корневой директории проекта.

### Проверка состояния базы данных

```bash
docker compose ps
```

Команда показывает состояние контейнеров, управляемых Docker Compose.

### Проверка корректности данных

```bash
bash model/run.sh check
bash model/query.sh check
```

Эти команды запускают проверки через сценарии аналитической модели.

### Просмотр доступных SQL-запросов

```bash
bash model/query.sh list
```

Команда предназначена для просмотра списка доступных аналитических запросов.

### Выполнение одного SQL-запроса

```bash
bash model/query.sh 03_average_check
```

`03_average_check` — пример имени SQL-файла без расширения `.sql`. Чтобы выполнить другой запрос, укажите его имя.

### Выполнение всех SQL-запросов

```bash
bash model/query.sh all
```

Команда запускает все аналитические SQL-запросы, предусмотренные сценарием.

### Полная демонстрация аналитической модели

```bash
bash model/demo.sh
```

Демонстрация включает проверки корректности данных и выполнение аналитических запросов.

## Проверка качества данных

Проверка качества данных необходима для обеспечения достоверности аналитических результатов.

В рамках валидации следует учитывать:

- уникальность первичных и составных ключей;
- наличие обязательных значений;
- корректность связей между сущностями;
- отсутствие размножения строк при соединении таблиц;
- согласованность агрегированных показателей;
- воспроизводимость результатов выполнения запросов.

Описание правил и результатов валидации находится в `VALIDATION.md`. SQL-проверки и сценарии верификации содержатся в соответствующих скриптах проекта.

## Аналитика и демонстрация

Проект предусматривает выполнение SQL-запросов для анализа данных маркетплейса и концепцию аналитического дашборда.

К основным направлениям относятся:

- анализ заказов и продаж;
- расчёт показателей на основе позиций заказов и платежей;
- анализ покупателей, товаров и продавцов;
- проверка качества данных;
- подготовка данных для визуализации.

Концепция дашборда описана в `dashboard_concept.md`.

Предлагаемые показатели, включая воронку пользовательских действий и финансовые метрики, следует считать реализованными только при наличии подтверждённых источников данных, согласованных формул и проверенных SQL-расчётов.

## Принципы работы

1. **Сохранение исходных данных.** Исходный слой не следует изменять без необходимости и согласованного процесса.
2. **Контроль зерна таблиц.** Для каждой сущности необходимо понимать, что представляет одна строка и какой ключ её идентифицирует.
3. **Корректность агрегатов.** До соединения таблиц нужно учитывать кардинальность связей и возможное размножение строк.
4. **Проверяемость.** Корректность модели и аналитических показателей подтверждается проверками и воспроизводимыми запросами.
