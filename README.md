# Capibara — аналитическая модель маркетплейса

Проект разработан в рамках хакатона Capibara и посвящён построению аналитической модели данных маркетплейса, проверке качества данных и подготовке аналитических запросов.

Репозиторий содержит SQL-скрипты для построения и проверки модели, сценарии запуска и демонстрации, результаты аналитической работы и документацию команды.

## Цели проекта

Основные задачи:

- Организовать данные маркетплейса в аналитическую модель.
- Подготовить SQL-скрипты для построения и проверки структуры данных.
- Проверить качество исходных данных и корректность ключей.
- Обеспечить воспроизводимый запуск основных сценариев проекта.
- Подготовить аналитические запросы и концепцию дашборда.
- Документировать архитектурные решения, ограничения и дальнейшие направления развития.

## Основные компоненты

### Построение модели

`build.sql` содержит SQL-логику построения модели данных. Он является одним из основных компонентов, отвечающих за подготовку аналитической структуры.

### Проверки данных

`check.sql` и `raw_fingerprint.sql` предназначены для проверок, связанных с данными и исходным слоем. Подробные условия проверок и ожидаемые результаты описаны в `VALIDATION.md` и соответствующих SQL-скриптах.

### Запуск и выполнение запросов

- `run.sh` — основной сценарий запуска.
- `run_profile.sh` — сценарий запуска с профилем.
- `query.sh` — выполнение аналитических запросов.
- `verify.sh` — сценарий проверки результатов.
- `demo.sh` — сценарий демонстрации проекта.

### Документация

Markdown-файлы в корне содержат описание решений команды, аналитических задач и дальнейшего развития проекта.

## Запуск проекта

Для начала работы клонируйте репозиторий:

```bash
git clone https://github.com/ILYA88G/rwb_hac.git
cd rwb_hac
```

Для выполнения сценариев `.sh` потребуется Bash-совместимая оболочка.

Перед запуском изучите инструкции и требования к окружению в `VALIDATION.md` и комментарии в соответствующих скриптах.

Основные сценарии проекта:

```bash
bash run.sh
bash verify.sh
bash demo.sh
```

Порядок запуска и необходимые параметры следует сверить с реализацией скриптов. Сценарии могут зависеть от доступности базы данных, исходных файлов и предварительно выполненных шагов.

## Проверка качества данных

Контроль качества данных является частью проекта. Для анализа и проверки используются SQL-скрипты и сценарии верификации.

При проверке аналитической модели важно учитывать:

- уникальность первичных и составных ключей;
- наличие обязательных значений;
- корректность связей между сущностями;
- отсутствие ошибочного размножения строк при соединении таблиц;
- согласованность агрегированных показателей;
- воспроизводимость результатов после повторного запуска.

Перечень конкретных проверок, их условия и ожидаемые результаты необходимо смотреть в `VALIDATION.md`, `check.sql` и `verify.sh`.

## Аналитика и демонстрация

`dashboard_concept.md` описывает концепцию аналитического дашборда и предполагаемые направления анализа.

`query.sh` предназначен для выполнения аналитических запросов, а `demo.sh` — для демонстрации проекта.

При подготовке аналитических показателей необходимо явно определять используемые данные, временной период, правила агрегации и формулы расчёта. Предполагаемые метрики и возможности не следует считать реализованными до подтверждения соответствующими запросами и результатами проверок.

## Принципы работы

1. **Воспроизводимость.** Запуск и проверка проекта должны выполняться по определённым сценариям.
2. **Контроль качества.** Корректность ключей, связей и агрегатов необходимо подтверждать проверками.
3. **Прозрачность расчётов.** Аналитические показатели должны иметь понятные определения и формулы.
4. **Документирование решений.** Архитектурные договорённости и ограничения фиксируются в документации.
5. **Разделение фактов и планов.** Реализованные функции следует отличать от предложений по развитию проекта.

## Статус проекта

Репозиторий содержит SQL-материалы, сценарии запуска и проверки, а также документацию по модели и аналитике. Фактический статус каждого компонента определяется его реализацией и результатами выполнения соответствующих проверок.
